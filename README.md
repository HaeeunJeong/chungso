# 청소봇 — Notion + 서버리스 추첨

Notion에서 인원·출결·개인 통계를 관리하고, Cloudflare Workers에서 청소 역할을 추첨합니다. PC나 상시 서버가 필요하지 않습니다.

**현재: 코드 작성 및 로컬 테스트 완료. Cloudflare 배포, Notion 토큰 연결, 버튼·공개 권한 설정은 아직 하지 않았습니다.** 실제 Notion API를 통한 종단 간 실행도 배포 후 확인해야 합니다.

## 처음 한 번 설정

1. https://dash.cloudflare.com/ 에서 본인 계정으로 로그인합니다.
2. https://www.notion.so/profile/integrations 에서 내부 연결을 만들고 콘텐츠 읽기·삽입·업데이트 권한을 켭니다. `clean bot` 페이지의 연결 메뉴에서 이 연결에 페이지와 하위 데이터베이스 접근을 허용합니다. ChatGPT의 Notion 연결과 별개입니다.
3. Node.js 22 이상 환경에서 아래 명령을 실행합니다.

```bash
git clone https://github.com/HaeeunJeong/chungso.git
cd chungso
npm test
npx wrangler@4 login
npx wrangler@4 secret put NOTION_TOKEN
npx wrangler@4 secret put WEBHOOK_SECRET
npm run deploy
```

`NOTION_TOKEN` 프롬프트에 Notion 내부 연결 토큰을 입력합니다. `WEBHOOK_SECRET`에는 비밀번호 관리자로 만든 32자 이상의 무작위 문자열을 입력합니다. 토큰과 비밀 키는 저장소나 채팅에 붙여 넣지 마세요. Wrangler가 Worker 생성을 묻는 경우 `chungso` 이름으로 생성합니다. 배포 출력의 실제 workers.dev URL을 사용합니다.

## Notion 버튼 두 개 설정

`청소 회차` 데이터베이스에 버튼 속성을 두 개 추가합니다. 각 버튼의 동작은 **웹훅 보내기**입니다.

| 버튼 이름 | URL | 사용자 지정 헤더 |
|---|---|---|
| 출결 준비 | 배포 URL 뒤 `/prepare` | `x-cleanbot-key`: WEBHOOK_SECRET 값 |
| 청소 시작! | 배포 URL 뒤 `/draw` | `x-cleanbot-key`: WEBHOOK_SECRET 값 |

청소 회차 행에서 실행하는 데이터베이스 버튼이어야 합니다. Notion 웹훅 JSON의 `data.id`를 회차 ID로 사용합니다. 직접 호출하는 경우 `{"session_id":"회차 page ID"}`도 지원합니다. 익명 조회자는 실행 권한이 없으며 비밀 키는 공개 페이지 본문에 적지 않습니다.

## 매번 사용하는 순서

1. 구성원에 이름을 등록하고 `등록 상태 = 활동`으로 선택합니다. 해제 시 행 삭제 대신 `등록 해제`를 선택합니다.
2. 청소 회차 행을 만들고 날짜와 `진행 상태 = 출결 입력`을 설정합니다.
3. **출결 준비**를 누르면 활동 구성원별 출결 행이 생성됩니다. 회차의 메모에 완료 표시가 나올 때까지 기다립니다. 한 명씩 저장하므로 수십 초 걸릴 수 있습니다.
4. 모든 출결을 출석·도망·부재 중 하나로 지정합니다. 공란이 있으면 추첨하지 않습니다.
5. **청소 시작!**을 누르면 출석 인원만 추첨합니다. 저장 중에는 기록을 수정하지 않습니다.
6. 진행 상태가 `확정`이 되면 역할과 통계를 확인합니다. 오류는 회차 메모에 표시됩니다. 원인을 수정한 뒤 같은 버튼을 누르면 저장된 결과부터 재개하며 다시 뽑지 않습니다.

준비 후 구성원을 새로 추가했다면 누락된 사람의 출결 행을 수동으로 추가합니다. 완료된 준비 버튼은 같은 회차에서 새로 실행하지 않습니다. 확정된 회차를 다시 뽑으려면 기존 회차를 취소하고 새 회차를 만듭니다. 과거 회차 통계를 수정하면 이후 추첨부터 반영되며, 과거 추첨 확률은 당시 값으로 보존됩니다.

## 추첨 규칙

- 역할은 청소기 A/B, 물걸레 A/B, 큰쓰레기 + 책상·모니터 먼지 제거, 공기청정기 필터 청소, 식탁 정리, 신발장 정리의 8개입니다.
- 출석 인원이 N명일 때 깍두기는 max(0, N-8)명입니다. 1~7명은 역할을 겸임하며 역할 수의 차이는 최대 1개입니다. 0명은 추첨을 중단합니다. 최대 80명을 지원합니다.
- 확정된 **이전 회차**의 출석 A회, 도망 D회를 사용합니다. 부재는 제외합니다.
- 초기 구현의 보상 가중치: `1 + 2 × (A+1)/(A+D+2)`. 신규 구성원은 2입니다. 기록이 적은 사람의 확률이 급변하지 않도록 보정한 값이며, 화면의 실제 출석률과 구분합니다.
- 깍두기 집합 S의 추첨 확률을 `S에 속한 사람들의 가중치 곱 / 모든 같은 크기 집합의 가중치 곱 합계`로 정의합니다. 동적 계획법으로 정확히 추첨합니다. 개인별 깍두기 확률도 이 분포에서 계산하며 모의실험 근사값이 아닙니다.
- 남은 인원을 무작위로 섞어 8개 역할을 배정합니다. 힘든 역할 불이익은 없습니다.
- `깍두기 확률 안내`는 **가장 최근 추첨 직전의 확률**입니다. 다음 회차의 출근 인원이 정해지기 전 미래 확률을 의미하지 않습니다. 회차별 확률은 출결 기록에 남습니다.

## 공개 조회

Notion `clean bot` 페이지에서 공유 → 일반 액세스 → 링크가 있는 웹의 모든 사용자 → 보기 가능으로 설정합니다. 관련 하위 데이터베이스·구성원 페이지도 실제 비로그인 창에서 열어 확인합니다. 관리자만 편집 권한을 유지합니다. 현재 저장소 코드가 Notion 공개 권한을 변경하지는 않습니다.

## 저장 및 오류 처리

SQLite 기반 Durable Object가 요청을 직렬화하고 추첨 결과를 먼저 영구 저장합니다. Notion 저장 실패 시 같은 결과를 재사용합니다. 오류는 최대 4번 자동 시도하며 이후 버튼으로 재시도할 수 있습니다. 알람마다 한 사람씩 처리합니다. `/health`는 연결 설정 유무만 반환하며 명단과 토큰은 반환하지 않습니다.

Notion은 여러 행의 원자적 갱신을 지원하지 않으므로 저장 도중에는 일부 역할이 먼저 보일 수 있습니다. **확정 상태를 최종 완료 기준으로 사용하세요.** API 타임아웃 직후 행 생성 결과가 불확실하면 재조회 후 이어서 처리합니다. 사용자가 저장 중 데이터를 수정하는 것을 기술적으로 잠그지는 못합니다.

## 파일

- `src/draw.js`: 가중치 추첨 및 정확한 개인별 확률
- `src/notion.js`: Notion API, 페이지네이션
- `src/worker.js`: 인증, 준비, 추첨, 영속 작업 큐
- `wrangler.jsonc`: 서버리스 배포 설정
- `test/`: 추첨·인증·재시도 테스트
